# ARCHIVE — API

Full interactive documentation is auto-generated by FastAPI and served
at:

- Swagger UI: `GET /api/docs`
- Raw OpenAPI schema: `GET /api/openapi.json`

This document is a quick reference; the OpenAPI docs are authoritative
for exact request/response schemas.

All endpoints except `/health`, `/api/auth/register`, and
`/api/auth/login` require an authenticated session (an `archive_session`
httpOnly cookie, set automatically on register/login). All
folder/file/trash endpoints are scoped to the authenticated user —
see `docs/SECURITY.md`.

## Auth

| Method | Path | Description |
|---|---|---|
| POST | `/api/auth/register` | Create an account. Sets the session cookie. |
| POST | `/api/auth/login` | Authenticate. Sets the session cookie. |
| POST | `/api/auth/logout` | Clears the session cookie. |
| GET | `/api/auth/me` | Returns the current user. |

## Folders

| Method | Path | Description |
|---|---|---|
| POST | `/api/folders` | Create a folder. `parent_id` optional (nesting). |
| GET | `/api/folders?parent_id=` | List folders under a parent (or root if omitted). |
| GET | `/api/folders/{id}` | Get one folder. |
| PATCH | `/api/folders/{id}` | Rename and/or move (change `parent_id`). |
| DELETE | `/api/folders/{id}` | Soft delete (moves to Trash). |

## Files

Uploading is a three-step flow — see `docs/ARCHITECTURE.md` for why.

| Method | Path | Description |
|---|---|---|
| POST | `/api/files/upload-url` | Step 1: validate + get a presigned PUT URL. |
| POST | `/api/files/complete` | Step 3: confirm upload, record checksum. |
| GET | `/api/files?folder_id=` | List files in a folder (or root if omitted). |
| GET | `/api/files/{id}` | Get one file's metadata. |
| GET | `/api/files/{id}/download-url` | Get a short-lived presigned GET URL. |
| PATCH | `/api/files/{id}` | Rename and/or move to another folder. |
| DELETE | `/api/files/{id}` | Soft delete (moves to Trash). |

Step 2 (the actual upload) is the browser issuing an HTTP `PUT` of the
raw file bytes directly to the `upload_url` returned in step 1, with
the header(s) in `required_headers` — it does not go through this API
at all.

## Trash

| Method | Path | Description |
|---|---|---|
| GET | `/api/trash` | List soft-deleted files and folders. |
| POST | `/api/trash/{id}/restore` | Restore a file or folder. |
| DELETE | `/api/trash/{id}` | Permanently delete (irreversible). |

## Search

| Method | Path | Description |
|---|---|---|
| GET | `/api/search?q=` | Filename/folder-name search (PostgreSQL `ILIKE`). |

## Storage

| Method | Path | Description |
|---|---|---|
| GET | `/api/storage/usage` | Returns `used_bytes`, `quota_bytes`, `remaining_bytes`. |

## Health

| Method | Path | Description |
|---|---|---|
| GET | `/health` | Public. Returns `{status, database, storage}` booleans only. |

## Example: full upload flow

```bash
# 1. Request a presigned upload URL
curl -X POST http://localhost:8000/api/files/upload-url \
  -b cookies.txt -H "Content-Type: application/json" \
  -d '{"filename":"report.pdf","mime_type":"application/pdf","size_bytes":102400}'
# => { "file_id": "...", "upload_url": "https://...", "required_headers": {"Content-Type": "application/pdf"} }

# 2. PUT the file directly to storage (not to this API)
curl -X PUT "<upload_url>" -H "Content-Type: application/pdf" --data-binary @report.pdf

# 3. Confirm completion with the file's SHA-256 checksum
curl -X POST http://localhost:8000/api/files/complete \
  -b cookies.txt -H "Content-Type: application/json" \
  -d '{"file_id":"...","checksum":"<sha256-hex>"}'
```
